# Bot Module User Guide

这份说明尽量用普通话说清楚：现在的 Bot 模块已经是一个独立区域，不会混到原来的数据面板里。原来的 Dashboard 还是看账户、仓位、挂单和交易数据；Bot 相关内容都在顶部的 `Bots` 入口里。

## 现在能做什么

### 1. Bot 管理

这里是每天最常用的地方，可以理解成“机器人列表”。

你可以做这些事：

- 新增一个 Bot，绑定主钱包、子账户、市场和策略。
- 编辑一个 Bot，比如改市场、改仓位上限、改报价间隔。
- 复制一个 Bot，适合快速给多个子账户开类似配置。
- 删除一个 Bot。
- 批量创建 Bot，适合一个策略同时铺到多个子账户。
- 单个启动、暂停、熔断。
- 实盘启动需要额外输入确认文字，避免误点。
- 批量启动、批量暂停。
- 导入/导出整套 Bot 配置，包含 Bot、策略和风控规则。

启动前会先做检查。比如缺少子账户、市场没填、最大下单价值不合理、风控规则不允许，都会先拦住，不会直接启动。

### 2. 策略管理

这里可以理解成“Bot 的模板库”。

策略不是实际运行的 Bot，它更像一套默认参数。新建 Bot 时选择策略，系统会把策略里的参数带过去。

现在策略可以编辑得比较细：

- 最大下单价值
- 最大仓位
- 日亏损上限
- 最大滑点
- 每分钟最多下单数
- 报价价差
- 挂单层数
- 每层间距
- 刷新间隔
- 最小/最大单笔数量
- 库存偏移
- 目标库存比例
- 多久撤掉旧挂单
- 是否只挂 maker 单
- 心跳超时
- 连续错误次数
- 最大延迟

简单理解：策略决定“这个 Bot 平时怎么挂单、挂多大、多久刷新、异常时多快停”。

### 3. 风险控制

这里是总保险丝。

你可以设置三类规则：

- 账户规则：限制某个主钱包下面最多跑多少 Bot、最大额度是多少。
- 市场规则：限制某个市场，比如 BTC，最多跑多少 Bot、最大额度是多少。
- 全局规则：限制整个 Bot 模块最多跑多少 Bot、总额度是多少。

启动 Bot 时会检查这些规则。如果 Bot 的额度超过规则，或者运行数量已经满了，系统会提示并阻止启动。

还有一个“全部紧急停止”按钮。它适合行情异常、网络异常、策略明显不对时使用。点了以后，所有 Bot 会进入熔断状态，需要人工恢复。

### 4. 告警中心

这里是问题列表。

比如某个 Bot 断连、延迟变高、连续报错、触发熔断，都应该出现在这里。当前前端已经做好列表、筛选、确认和全部确认，真实告警内容等后端 Runner 接上后会更完整。

## 三种运行模式

### 仅监控

只看行情和账户变化，不模拟下单，也不真实下单。

适合先观察策略信号是否正常。

### 模拟

会按策略“假装下单”，用于看策略大概会怎么跑，但不会动真钱。

适合上线前测试。

### 实盘

会真实下单。

这个模式风险最高，所以界面上会更明显地提醒，并且启动前会做更多检查。真正接后端时，后端也必须再次检查权限和风控，不能只相信前端。

## 当前哪些是真功能，哪些是模拟

已经完成的前端主框架：

- 独立 Bot 模块入口。
- Bot 管理、策略管理、风险控制、告警中心四个页面。
- 新增、编辑、复制、删除、批量创建、批量启停。
- 策略可编辑。
- 风控规则可编辑。
- 启动前检查。
- 导入/导出配置。
- 后端接口契约已经预留。
- 没有后端时会自动用浏览器本地数据模拟，方便先看 UI 和流程。

还没有真正接上的部分：

- 真正跑策略的后台服务。
- 真正提交订单的交易执行服务。
- 真正行情订阅和成交回报。
- 真正的服务端风控复查。
- 更完整的操作审计和权限系统。

## 接真实交易前必须补上的东西

### 1. 后端 Runner

Runner 可以理解成“真正干活的机器人程序”。前端只是负责管理和开关，真正监听行情、计算价格、下单、撤单，都应该由 Runner 做。

### 2. 服务端风控

前端的风控检查是为了让用户少犯错，但真正上线时，后端必须再检查一遍。

原因很简单：实盘交易不能只靠浏览器保证安全。

### 3. 权限和操作记录

需要知道是谁启动了 Bot、谁改了策略、谁点了紧急停止。以后多账号、多成员操作时，这个很重要。

### 4. 真实告警

比如断线、连续下单失败、行情源异常、账户余额不足、延迟过高，都应该由后端产生告警，再显示到前端。

## 推荐上线顺序

1. 先保持当前前端主框架稳定，继续补 UI 细节。
2. 接一个只读 Runner，只监控行情和账户，不下单。
3. 接模拟模式，用真实行情跑模拟下单。
4. 接服务端风控和操作记录。
5. 小额度开放实盘，只允许白名单账户使用。
6. 再考虑多策略、多市场、大规模批量运行。

## 是否值得继续做

值得做，但建议分阶段。

原因是：

- 这个项目本来就是多账户数据面板，天然适合扩展成 Bot 管理台。
- Bot 模块独立后，不会污染原来的数据面板。
- 先做管理和风控，再接真实交易，风险更可控。
- 后续如果做多账号做市，管理台会比脚本分散运行更安全、更好维护。

不建议一开始就直接上实盘自动交易。更稳的路线是：先监控，再模拟，再小额实盘。
